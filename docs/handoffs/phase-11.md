## Changes and decisions

Accepted requirements: first delivered purchase in available history, fractional multi-product weights summing to one, mature 60/90-day contribution separate from partial cohorts, repeat buyers/refunds/missing costs/incomplete history without duplicate value or future leakage. [Cohort contract](../phase-11-cohorts.md) records exact implementation defaults and limits; [policy](../../backend/advergent/cohorts.py), [Exasol adapter](../../backend/advergent/cohorts_sql.py), authenticated API and [UI](../../frontend/src/Cohorts.tsx) implement them. Generated OpenAPI and frontend types carry the response.

Rolling half-open exact-time windows and lexical equal-delivery order ties are implementation defaults. Asia/Kolkata determines acquisition month. First-order historical net merchandise weights exclude tax, shipping and future refunds; same-product variants combine. All-zero first merchandise abstains. Rational weights sum exactly to one, and known positive/negative customer totals allocate whole paise with deterministic residuals. Repeat purchases and dated refunds/recoveries remain in the original customer cohort. Acquisition-order pre-delivery expenses count once; other pre-acquisition events are explicitly excluded/countable. Mature means observed window, not completion of every eventual return.

History remains incomplete because no exhaustive older-order declaration exists. Earliest input observation/finance as-of/actual time bounds contribution; `as_of` can only move earlier. Missing event costs preserve unknown full totals, with separately labelled event coverage and known-customer subtotals. No cash/reserves/ad spend/platform claims/funnel events enter contribution. Retrospective snapshots are not proof of historical knowledge or a predictive backtest. No new migration/importer/worker/publication pointer/action interface. INR 0.
