# Phase 9 clearance contract

Phase 9 only: synthetic deadstock ranking and configurable read-only scenarios over real local Exasol and existing PostgreSQL publication identities. Accepted requirements are A18, no-action comparison, stock/cost coverage/contribution/margin constraints, labelled assumptions, no discount/bundle/campaign publishing or advertising mutations, preserved history and INR 0. Gate evidence is recorded separately in the [Phase 9 handoff](handoffs/phase-9.md).

## Evidence and ownership

[Clearance analytics](../backend/advergent/clearance_sql.py) verifies the pinned inventory dataset through the existing inventory/finance/mapping/reporting adapters, verifies catalog typed columns against retained commerce source, then joins exact variant IDs, prospective catalog prices/COGS and available-minus-separate-reserve stock in Exasol. Commitments are already excluded. Receipts never enter current stock. Missing catalog COGS stay null. Historical finance line costs, targeted corrections and reserves are never overwritten by catalog costs or prospective assumptions. No operational source becomes an analytical fallback.

Inventory pins finance, commerce, ads and attribution; clearance uses those exact IDs even if current pointers change. The authenticated API checks coherent current pointers before querying and checks them again afterward. Changed pointers or stale/future selected stock make the comparison infeasible. Source observation timestamps and all five pinned IDs accompany results. The input-observation map contains only publications whose current IDs match the pinned IDs; a changed pointer cannot substitute a new cutoff for old evidence. No query or replay renews a source observation. Historical source cutoffs remain visible. Diagnostics and execution are not dependencies and clearance grants no execution authority.

PostgreSQL retains existing publication/configuration and approval/action history. Clearance creates no new tables, runs, approvals, simulator state or publication pointer. Scenario terms are ephemeral authenticated request inputs, returned with results for reproduction. There is no saved scenario library, publishing interface or executor connection. GET `/api/clearance` computes the labelled default; POST `/api/clearance/scenario` accepts bounded strict integer terms under existing authentication and origin protection. Unknown/duplicate variants, extra fields, booleans/fractional money, negative costs/floors and invalid bounds reject. Analytics unavailability returns no ranking, selected evidence, comparison or query time; retained IDs/cutoffs identify the unavailable inputs. Operational failure remains sanitized 503.

## Deadstock ranking defaults

Each variant uses the existing independent synthetic warehouse eligible-unit counters and measured in-stock exposure. These counters add no commerce sales or finance revenue. The inherited ten-unit/seven-day demand floor applies. Insufficient/zero/missing exposure yields unknown excess and unranked uncertainty, never infinite cover or invented zero demand.

Default horizon is 30 days. Excess units = max(0, sellable units - floor(reliable observed daily rate × horizon)). Default assumed stock age is uniformly 120 days, and candidate age threshold is 90 days. Candidate requires positive excess and assumed age at least threshold. Rank descending by assumed age × excess units, with lexical variant ID ties and uncertain rows last. Zero scores remain visible. These are synthetic configuration assumptions, not observed lot ages, evidence that all units arrived together, a calibrated deadstock classifier or a demand forecast. Product/size identity, sellable units, demand sufficiency, COGS status and individual stock freshness remain visible. A candidate flag on stale evidence is historical descriptive output, never actionable eligibility.

## Baseline, markdown, bundles and spend

The selected mix has one to twenty unique variants with positive units per bundle. Both alternatives use that identical composition and horizon. Baseline assumes an explicit number of bundles sold at full catalog price and zero additional spend; it means no new clearance intervention, not zero existing merchant advertising. Historical advertising/finance figures are not added again. Scenario independently assumes bundle sales, a uniform markdown and one total additional-spend amount. There is no response model linking spend/discount to sales. No forecast confidence, causal lift or effectiveness is established. Alternatives must never be added together.

Defaults select v6, one baseline bundle versus three scenario bundles, 50% markdown and zero additional spend. The default is an A18 counterexample, not an optimal recommendation. User can change every exposed term, component, unit count and floor. Each discounted unit price is floor(catalog paise × (10000 - markdown basis points) / 10000), then multiplied by requested units. Bundle revenue sums its components exactly. All money is integer INR paise; no binary float ledger arithmetic occurs. Prices/revenue exclude tax and assume full delivery. Tax, payment collection, COD/RTO mix and calibrated return probabilities require richer evidence; they are not quietly inferred from past orders.

Prospective contribution = scenario merchandise revenue - selected units' catalog COGS - variable cost - expected return loss - additional spend - residual-stock holding cost. Default variable expense is INR 100 per sold unit, expected return loss INR 10 per sold unit, and holding cost five paise per unsold unit per day. Holding applies to all remaining selected stock for the full horizon, assuming sales occur at its start; it is not an observed storage expense or a sales-timing model. Expected return loss is a standalone net-loss assumption, not a second deduction of historical finance reserves. Catalog actual/estimated/missing status remains visible; all evidence is synthetic. Missing any required cost makes full expected contribution, margin and contribution delta unknown; no covered subtotal becomes a full estimate. COGS unit coverage is reported separately from other cost completeness.

## Limits and A18

Every component must fit observed sellable stock; requested units are never clamped to hide infeasibility. An impossible baseline also blocks feasibility. Default contribution floor is zero paise, configurable upward; default after-spend-and-holding contribution margin floor is 1,000 basis points, configurable from zero to 10,000. Both alternatives display their own limits and losses; a loss-making no-action baseline may legitimately be improved. Margin comparison uses exact cross multiplication before display rounding. Zero-revenue margin is undefined; a zero-revenue negative contribution still fails the nonnegative contribution floor. Known zero costs remain distinct from missing values, including zero-unit/zero-residual cases requiring no corresponding cost.

`limits_pass` means the alternative meets stock and economic checks. `feasible` additionally requires current coherent dependencies, fresh selected stock, sufficient selected demand and a stock-valid baseline. Feasibility is a synthetic what-if result only. `publishing_enabled=false` and `mutation_enabled=false` always, including for feasible comparisons. No advertising resource mapping or capability is invented from a product bundle. Any future advertising change still requires the separate exact approval/execution contract and a separately authorized phase.

The default pinned v6 case has 40 sellable units, INR 810 full price and INR 321 prospective COGS. Baseline revenue/contribution are 81,000/32,050 paise. Three units at half price yield 121,500 revenue but negative 13,350 contribution paise. Revenue rises 40,500 and contribution falls 45,400 paise. Both contribution and margin floors fail. Historical stock is stale, independently blocking feasibility. The separate hand-calculated isolated fixture uses INR 800/440 price/COGS and expects 80,000/19,150 baseline versus 120,000/negative 50,550 scenario paise; these two evidence cases must not be conflated.
