# Phase 7 diagnostics contract

Implemented scope: synthetic fixture observations, real local PostgreSQL/Exasol, authenticated read-only diagnostic reviews. Executed results belong in the [Phase 7 handoff](handoffs/phase-7.md). A22 distinguishes transient uncertainty from repeated 404 evidence; A23 compares the selected variant; A24 preserves untrusted text as escaped evidence. No real crawling, model API, advertising mutation, approval executor or paid provisioning is included.

## Source and defaults

[Models/policy](../backend/advergent/diagnostics.py), [generator](../backend/advergent/diagnostics_fixture.py) and [source](../fixtures/diagnostics-v1.json) supply explicit destination attempts and independent creative impression/click counters. Counters do not add commerce orders, revenue or spend. IDs bind exact platform/account/resource, selected commerce variant, URL, observation time and source outcome. URLs are inert text, never fetched or followed. Page text cannot become instructions. Strict models reject extra fields, duplicate evidence IDs, duplicate creative/window identities, future observations, non-seven-day windows and clicks exceeding impressions. INR prices are integer paise; missing prices stay unknown.

Implementation defaults, not merchant-confirmed or calibrated benchmarks: two consecutive not-found observations separated by at least 60 seconds, both no older than 900 seconds; 900-second current-evidence limit; two adjacent closed seven-day windows; at least 1,000 impressions and 20 clicks in **each** window; relative CTR decline of at least 30%. Retry count/spacing, freshness and evidence/drop thresholds are source configuration. Exactly 900 seconds is fresh. Exactly 30% decline qualifies. Evidence floors do not imply statistical significance.

## Destination and price interpretation

Group attempts by exact resource, variant and URL and order by observation time. Timeout/server error remains uncertain even when repeated. A single 404 or tightly spaced repeated 404 remains uncertain. A healthy response or bot block breaks the not-found sequence; two sufficiently spaced fresh consecutive 404s establish a confirmed fixture issue. This is not proof of a real live outage. Redirects require review and retain their target as data; bot blocks remain uncertain and never establish a broken destination. Archived catalog products receive a distinct archived-product status. Stale observations override current destination conclusions; replay cannot refresh them.

Successful pages compare page-selected variant to requested variant before comparing price. A different selected variant is uncertain, never a product-global mismatch. For the same variant, compare catalog, page and advertised integer-paise prices. Missing page/advertised price stays unknown. An offer expiring at or before evaluation receives expired-offer status rather than a normal mismatch. Redirect/error/bot outcomes do not produce a successful-page price verdict. Evidence retains the original page/advertised prices, selected variant, expiry and all attempts. Archived or out-of-scope destinations cannot enable creative suggestions.

## Fatigue and suggestions

Group by exact platform/account/resource/creative ID. Require exactly two adjacent closed seven-day windows with the same audience, placement and objective. Changed segmentation or gaps abstain as incomparable. Sparse, zero-volume, missing or excess windows abstain; zero denominators remain null. Compare exact decimal CTR (clicks/impressions); no display rounding enters the policy. The current window must be fresh. A qualifying decline is **possible fatigue**, a descriptive signal with no causal or model-effectiveness claim. Impressions/clicks are independent synthetic reporting observations, not verified platform delivery or controlled experimental data.

Only a possible-fatigue signal with cleared blockers produces a fixed review template. Resolve the pinned reviewed mapping again at actual query time using Phase 4 validity, confidence and override rules. Native hints and low-confidence/ambiguous/unmapped resources do not authorize product suggestions. Every mapped product must have clear, fresh Phase 6 inventory and active catalog status; every supplied destination must be within that exact reviewed set and healthy with matching selected-variant price. Missing destination evidence, changed upstream inputs and any destination/price issue withhold suggestions. Mixed resources remain whole-set reviews; no unsupported narrow control is inferred.

Suggestions use a fixed sentence proposing size/color presentation, with facts from structured pinned catalog size/color fields. Titles and page text remain quoted/escaped evidence; they never enter a prompt, execute code, grant approval or invent a discount, material, scarcity or performance promise. React escapes all rendered strings/JSON. No HTML injection or navigable untrusted URL is used. Exact capability evidence, status/product controls and shared-budget members remain visible; review does not imply an edit capability. Every review is advisory=true, approval_required=true and mutation_enabled=false. There are no approval or mutation endpoints.

## Ownership, publication and failure

[Migration 007](../migrations/007_diagnostics.sql) owns immutable full configuration, pinned inventory identity, attempts and an independent PostgreSQL publication. Inventory pins finance and commerce/ads/attribution. Imports acquire all upstream locks plus a diagnostics lock and require coherent current dependencies. UUID namespace diagnostics-v1: uses exact source SHA-256 plus inventory identity. Successful replay preserves original source and completion timestamps. A new configuration uses a complete immutable CLI source.

[Exasol adapter](../backend/advergent/diagnostics_sql.py) owns typed attempts/windows, retained payloads, configuration/input completion marker, exact selected-variant SQL price joins and nullable SQL CTR evidence. Vendor-neutral Python applies diagnostic policy to verified analytical source/commerce/inventory features. Full source/core/configuration read-back and dependency checks precede publication. Exasol represents empty strings as NULL; typed verification accounts for this only for empty-string source fields while preserving original payload text. SQL load failure rolls back observations/windows/marker. Failure after analytical commit retains the previous pointer and retry verifies/reuses the orphan. No cross-store atomicity or automatic cleanup is claimed.

Authenticated GET /api/diagnostics and [UI](../frontend/src/Diagnostics.tsx) expose evidence, assumptions, mappings, capabilities, blockers and query/publication/hash/input identities. API evaluates at actual UTC; deterministic adapter tests may evaluate at the fixture clock. Changed upstream pointers retain the pinned view and withhold suggestions. Actual analytics failure returns null current data/query time with retained publication evidence. PostgreSQL configuration never becomes an analytical fallback. Private credentials, TLS pin, launcher state and volumes remain untouched.

## Commands and limits

Load private environment with `. .\scripts\env.ps1`; run `.\.venv\Scripts\python.exe -m advergent.diagnostics_fixture`, then `worker migrate` and `worker diagnostics` with the same executable. `worker diagnostics --fixture PATH` imports another complete immutable source. Run source-mutating checks sequentially with Exasol healthy. After actual outage, restore launcher and all seven default publications before final healthy checks. Exact commands/results: [handoff](handoffs/phase-7.md).

Synthetic observations cannot prove real destination reachability, live platform capabilities, catalog/source completeness, statistical fatigue, ad effectiveness, calibrated thresholds or merchant-approved creative. Historical defaults stay stale. No real crawling, LLM calls, advertising write, Phase 8/later module, provisioning, billing change, commit or push. INR 0 remains required.
